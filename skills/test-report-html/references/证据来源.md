# 证据来源

`collect_evidence.py` 会把下面这些文件读成一份 `evidence.json`。找不到证据时，报告里就只剩「未走查」。

## 自动化测试报告

| 框架 | 默认落点 | 识别方式 |
|---|---|---|
| Maven Surefire | `<module>/target/surefire-reports/TEST-*.xml` | 数 `<testcase>` |
| Maven Failsafe | `<module>/target/failsafe-reports/TEST-*.xml` | 用 `--include "**/failsafe-reports/TEST-*.xml"` |
| Gradle | `<module>/build/test-results/**/TEST-*.xml` | 数 `<testcase>` |
| pytest | `--junitxml=test-results/junit.xml` 时落在 `test-results/**/*.xml` | 数 `<testcase>` |
| Jest / Vitest | 配 `junit` reporter 输出 `junit*.xml` | 数 `<testcase>` |
| Go | `go test -json` 或 `gotestsum --junitfile` | 转成 junit XML 再扫 |

### 计数只认 `<testcase>`

JUnit 的 `<testsuite tests="N">` 属性在 `@Nested` 用例上会少报——外层 suite 报 3、实际 8 个 testcase 是常见形态。用属性计数会得出「比上次少了」的假回归，或者按下限报「全部通过」。

所以：`tests` = testcase 元素个数；`failures` / `errors` / `skipped` = 挂在 testcase 下的 `<failure>` / `<error>` / `<skipped>` 个数，而不是 suite 上的同名属性。

### 报告新鲜度

`collect_evidence.py` 会记每份报告的 mtime，并：

- 最新一份报告超过 `--max-age-days`（默认 7 天）→ 告警「先重跑测试」；
- 有 failures / errors → 告警「报告里不能写全部通过」；
- XML 解析失败 → 跳过并列出文件名，不会静默当成 0。

**判断「这次跑出来的报告」要看 mtime**。仓库里的 surefire XML 可能是上一次的，把旧报告当新读数，就是这个工具最容易骗人的地方。

### 孤立报告：比「过期」更常见的一种骗法

`--max-age-days` 只看**最新**那份。如果同一批里混着几份上一轮留下、这次没被覆盖的报告（典型来源：测试类被删了，`target/` 里的 XML 不会跟着消失），最新那份是新的，告警一句都不会响，用例数却虚高。

所以 `collect_evidence.py` 另有一条判据：以**本次扫描到的最新 mtime** 为基准，早于 `--stale-after-hours`（默认 24 小时）的列入 `test_reports.stale` 并告警。它默认**仍计入**统计（保守），确认是残留就删文件，或加 `--exclude-stale` 重跑。

措辞是「疑似」，不是「过期」：低频跑的测试确实会落在阈值外，误报要留出口，由人判断。

## 运行时结果

放在 `test/results/` 下的 JSON，由你自己的脚本写出。认两种形状：

```json
[{"flow": "01 认证", "status": "PASS", "detail": "8 个身份", "seconds": 1.3}]
```

```json
{"name": "smoke_matrix", "items": [...], "count": 146}
```

`status` 不是 `PASS` / `OK` / `SKIP` 的一律算失败，所以脚本里别用 `true` / `done` 这种自造状态。

配套两个骨架：

- `assets/harness.py` → 端到端脚本，按业务闭环记 PASS/FAIL，失败也落盘；
- `assets/smoke_matrix.py` → 只读接口 × 角色矩阵，跑完写 `smoke_matrix.json`。

## 拿不到证据时怎么办

| 想写 | 但没有证据 | 正确做法 |
|---|---|---|
| 「UI 走查 40 页全部通过」 | 没截图、没走查记录 | 写「未走查」，或这次真的走一遍并留截图路径 |
| 「接口全部正常」 | 只跑过冒烟，没跑写接口 | 写清「只读接口冒烟」，别扩大成全接口 |
| 「并发安全」 | 没并发用例 | 补一个并发测试再写；没有就写「未验证」 |

报告的信用来自「说过的话都能查」，一次无证据的断言就把它花掉了。
