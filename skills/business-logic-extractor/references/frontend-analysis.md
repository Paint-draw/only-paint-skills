# 前端代码业务逻辑分析指引

前端代码蕴含大量业务逻辑，但常被误认为"只是 UI"。实际上，前端承载了：用户交互流程、客户端校验、状态管理、缓存策略、权限控制、错误处理、防重复提交——这些都是业务规格不可或缺的部分。

## 分析目标

从前端代码中提取：
1. **用户能做什么**（交互入口、操作流程）
2. **用户看到什么**（UI 状态、数据展示规则）
3. **客户端如何校验**（校验规则、校验时机）
4. **客户端如何与后端协作**（API 调用时机、轮询、重试）
5. **客户端如何处理异常**（网络错误、业务错误、空状态）

## 按文件类型分析

### 1. 页面/视图组件（Pages / Views）

这是用户交互的入口，承载主要业务流程。

**要提取的信息**：
- 页面的入口路由和参数
- 页面加载时调用哪些 API、按什么顺序
- 页面有哪些 UI 状态（加载中、空数据、错误、正常、禁用）
- 用户可执行哪些操作（按钮、链接、手势）
- 每个操作触发什么（API 调用、路由跳转、弹窗、状态变更）
- 操作前的前置校验（如"未填写手机号时禁用提交按钮"）
- 操作后的反馈（toast、弹窗、跳转、按钮状态变化）
- 页面离开时的处理（未保存提示、轮询清理）

**分析技巧**：
- 从 `useEffect` / `mounted` / `onLoad` 等生命周期钩子入手，找页面初始化逻辑
- 查看所有 `onClick` / `onSubmit` / `@click` 等事件绑定，找用户操作入口
- 查看条件渲染（`v-if` / `&&` / `ternary`），找 UI 状态分支
- 查看路由守卫（`beforeRouteEnter` / `getServerSideProps`），找权限控制

### 2. 表单与校验（Forms & Validation）

前端校验是业务规则的第一道防线，往往与后端校验不完全一致。

**要提取的信息**：
- 每个表单字段的校验规则（必填、格式、长度、范围、自定义）
- 校验时机（onChange、onBlur、onSubmit）
- 跨字段校验（如"密码与确认密码一致"、"结束时间大于开始时间"）
- 异步校验（如"用户名是否已存在"）
- 校验失败的展示方式（行内错误、错误汇总、toast）
- 表单提交前的最终校验
- 表单重置/预填逻辑

**分析技巧**：
- 查找校验库的使用（Yup、Joi、Zod、async-validator、vee-validate、react-hook-form 的 resolver）
- 查找手写校验函数（通常命名含 `validate`、`check`、`verify`）
- 查看表单提交函数的开头，通常有校验逻辑
- 注意 disabled 按钮的条件——那也是校验规则

**重要**：前端校验规则要逐条记录，并标注"前端校验"以区别于后端校验。如果前后端校验不一致，要分别记录并标注差异。

### 3. 状态管理（State Management）

状态管理库（Redux、Vuex、Pinia、Zustand、MobX、Context 等）存储客户端业务状态。

**要提取的信息**：
- 存储了哪些业务数据（用户信息、购物车、订单列表、筛选条件）
- 状态如何初始化（从 API 加载、从本地存储恢复、默认值）
- 状态如何更新（哪些 action/mutation 改变状态）
- 状态如何派生（selector/computed 的计算逻辑）
- 状态何时清除（登出、页面离开、过期）
- 状态持久化策略（localStorage、sessionStorage、cookie）

**分析技巧**：
- 从 store 的定义文件入手，列出所有 state 字段
- 查看 reducer/mutation，找状态变更逻辑
- 查看 selector/computed，找派生数据计算
- 查看持久化配置（如 redux-persist、pinia-plugin-persistedstate）

### 4. API 客户端（API Client）

API 调用层揭示前后端契约和客户端的调用策略。

**要提取的信息**：
- 调用了哪些后端接口（URL、方法、参数、响应）
- 调用时机（页面加载、用户操作、定时轮询、WebSocket 推送）
- 请求拦截（添加 token、签名、traceId）
- 响应拦截（统一错误处理、token 刷新、重试）
- 重试策略（哪些错误重试、重试几次、退避算法）
- 超时设置
- 并发控制（请求取消、防抖、节流）
- 缓存策略（哪些请求缓存、缓存多久）

**分析技巧**：
- 查找 axios/fetch 的封装层，通常有统一拦截器
- 查找 API 定义文件（通常命名含 `api`、`service`、`request`）
- 查找轮询逻辑（`setInterval` + `fetch`、`react-query` 的 `refetchInterval`）
- 查找请求取消（`AbortController`、`CancelToken`）

### 5. 路由与权限（Routing & Permissions）

路由配置揭示页面结构和权限控制。

**要提取的信息**：
- 所有相关路由及其参数
- 路由守卫（登录要求、角色要求、数据预加载）
- 路由跳转逻辑（什么情况下跳哪）
- 菜单/导航的显隐规则
- 按钮级权限控制（`v-permission`、`hasPermission`）

**分析技巧**：
- 查看路由配置文件（`routes.ts`、`router/index.ts`）
- 查看全局守卫（`beforeEach`、`beforeEach` in Next.js middleware）
- 查看权限指令/组件（`v-permission`、`<HasPermission>`）

### 6. 工具函数与常量（Utils & Constants）

工具函数和常量文件往往包含业务规则。

**要提取的信息**：
- 业务常量（状态枚举、错误码、配置阈值）
- 业务计算函数（价格计算、折扣计算、时间格式化）
- 业务判断函数（`isExpired`、`canRefund`、`isVip`）
- 格式化函数（金额、日期、手机号脱敏）

**分析技巧**：
- 查找 `constants`、`enum`、`config` 命名的文件
- 查找 `utils`、`helpers` 目录下的业务相关函数
- 注意那些"看起来简单"的函数——它们可能编码了重要业务规则

### 7. 国际化文案（i18n）

i18n 文案揭示所有用户可见的状态和错误场景。

**要提取的信息**：
- 功能相关的所有文案 key 及其值
- 文案中的变量插值（揭示展示逻辑）
- 错误文案（揭示可能的错误场景）
- 空状态文案（揭示空数据处理）

**分析技巧**：
- 在 locale 文件中按功能关键词搜索
- 对照代码中的 `$t('payment.success')` 找到对应文案
- 注意文案中的 plural 规则（单复数）

## 前端特有业务逻辑清单

以下是前端特有、容易遗漏的业务逻辑：

### 交互逻辑
- [ ] 按钮防重复点击（loading 态、节流、防抖）
- [ ] 表单未保存离开提示
- [ ] 列表无限滚动/分页加载
- [ ] 下拉刷新
- [ ] 返回键拦截
- [ ] 离开页面时清理资源（定时器、WebSocket）

### 展示逻辑
- [ ] 金额格式化（千分位、小数位、货币符号）
- [ ] 日期格式化（相对时间、绝对时间、时区转换）
- [ ] 手机号/身份证/银行卡脱敏
- [ ] 空状态展示
- [ ] 骨架屏/加载动画
- [ ] 错误态展示
- [ ] 数据为空时的引导操作

### 缓存逻辑
- [ ] 接口响应缓存
- [ ] 草稿本地保存
- [ ] 图片/资源缓存
- [ ] 用户偏好本地存储

### 实时性逻辑
- [ ] 轮询频率与停止条件
- [ ] WebSocket 连接与重连
- [ ] 数据过期自动刷新
- [ ] 后台返回时刷新数据

### 权限逻辑
- [ ] 路由级权限
- [ ] 按钮/操作级权限
- [ ] 数据范围权限（只看自己的数据）
- [ ] 字段级权限（某些字段对某些角色隐藏）

## 常见陷阱

1. **只看组件不看 hook/util**：现代前端把逻辑抽到自定义 hook 和 util 函数里，组件只是壳。一定要追到 hook 和 util。

2. **忽略 CSS/样式中的业务规则**：有些业务规则藏在样式里，如"VIP 用户显示金色徽章"（`.vip-badge` 类的条件渲染）、"库存为 0 时按钮置灰"（`:disabled="stock === 0"`）。

3. **忽略 TypeScript 类型定义**：类型定义（interface、type）揭示了数据结构和字段约束，是业务规格的重要输入。

4. **忽略 mock 数据和测试**：前端测试和 mock 数据往往揭示预期行为和边界情况。

5. **把框架特性当成业务逻辑**：`useState`、`useEffect` 是 React 的实现细节，不是业务逻辑。业务逻辑是"为什么用 useEffect 在这里调 API"——即"页面加载时需要获取订单详情"。

6. **忽略环境变量**：`NEXT_PUBLIC_API_URL`、`VITE_MAX_UPLOAD_SIZE` 等环境变量往往承载业务配置。

## 输出建议

前端分析结果在规格文档中主要落入以下章节：
- **第 3 章 用户流程**：交互流程、状态转换
- **第 7 章 前端行为**：UI 状态、客户端校验、交互细节、错误展示
- **第 6 章 业务规则**：客户端校验规则（标注"前端校验"）
- **第 5 章 API 契约**：从客户端视角补充调用时机、缓存策略
- **第 9 章 安全与合规**：前端权限控制
