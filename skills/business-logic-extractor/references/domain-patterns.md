# 常见业务领域模式参考

针对常见业务功能，列出分析时必须重点关注的要点。这些是基于行业经验的"易遗漏点清单"，分析对应领域时逐项检查。

---

## 1. 支付领域（Payment）

### 核心实体
- 支付订单（Payment Order）：记录一次支付意图
- 支付渠道交易（Channel Transaction）：记录与第三方渠道的交互
- 退款单（Refund Order）：记录退款意图
- 对账记录（Reconciliation Record）：记录对账结果

### 必查要点

**支付创建**
- [ ] 订单状态校验（未支付、未关闭、未退款）
- [ ] 金额校验（大于 0、与业务订单金额一致、币种一致）
- [ ] 防重复支付（同一业务订单同时只能有一个进行中的支付）
- [ ] 支付渠道选择逻辑（用户选择 vs 系统路由）
- [ ] 渠道侧下单（如微信统一下单、支付宝预下单）的参数构造
- [ ] 预支付信息的保存（prepay_id、code_url 等）

**支付回调/通知**
- [ ] 签名验证（防伪造）
- [ ] 幂等处理（同一通知多次发送）
- [ ] 金额校验（回调金额与订单金额一致）
- [ ] 状态校验（订单当前状态允许此回调）
- [ ] 异步处理 vs 同步响应（先响应再处理，避免超时）
- [ ] 回调失败的渠道侧重发机制处理

**支付状态查询**
- [ ] 主动查询的触发时机（用户主动查、定时补偿查）
- [ ] 查询结果与本地状态不一致的处理
- [ ] 查询频率限制

**退款**
- [ ] 退款金额校验（不超过原支付金额、不超过可退金额）
- [ ] 部分退款支持（多次退款的累计校验）
- [ ] 退款状态机（申请中、退款中、成功、失败）
- [ ] 退款回调处理（同支付回调要点）
- [ ] 退款失败的后续处理（重试、人工介入）

**对账**
- [ ] 对账频率与触发方式
- [ ] 差异类型（平台有渠道无、渠道有平台无、金额不一致）
- [ ] 差异处理流程（自动补偿、人工介入）

**资金安全**
- [ ] 金额全程整型存储（分），禁止浮点
- [ ] 金额计算精度（舍入规则）
- [ ] 敏感信息脱敏（卡号、openid）
- [ ] 操作审计日志

**常见边界情况**
- 支付超时（订单关闭后渠道才回调）
- 用户支付后立即退款
- 渠道侧重复回调
- 网络抖动导致查询失败
- 跨日支付（时区问题）
- 金额为 0 的支付（是否允许）

## 2. 优惠券领域（Coupon）

### 核心实体
- 优惠券模板（Coupon Template）：定义券的规则
- 优惠券实例（Coupon Instance）：用户领取的券
- 核销记录（Redemption Record）：使用记录

### 必查要点

**券模板规则**
- [ ] 券类型（满减、折扣、立减、兑换）
- [ ] 面值与门槛（满 X 减 Y、折扣率、最高抵扣额）
- [ ] 适用范围（全场、指定商品、指定分类、指定商户）
- [ ] 排他规则（能否与其他券叠加、能否与活动叠加）
- [ ] 有效期（绝对时间、相对时间、领取后 N 天）
- [ ] 发放总量限制
- [ ] 每人领取限制
- [ ] 每人持有上限
- [ ] 每日使用限制

**领取逻辑**
- [ ] 领取资格校验（用户等级、新老客、是否已领）
- [ ] 库存扣减（防超发——并发控制）
- [ ] 每人领取次数限制（防刷）
- [ ] 领取后的有效期计算
- [ ] 领取事件发布（用于通知、统计）

**核销逻辑**
- [ ] 券状态校验（未使用、未过期）
- [ ] 适用性校验（商品范围、门槛金额）
- [ ] 抵扣金额计算（含最高抵扣、向下取整规则）
- [ ] 多券叠加规则（如允许，计算顺序）
- [ ] 与其他优惠的叠加规则（会员价、活动价）
- [ ] 核销时机（下单锁定、支付成功确认、取消释放）
- [ ] 防重复核销

**退券逻辑**
- [ ] 订单取消时券释放
- [ ] 订单退款时券是否返还（部分退款如何处理）
- [ ] 退券后的状态与有效期（恢复原有效期 vs 延长）
- [ ] 退券次数限制（防刷）

**常见边界情况**
- 券过期时刻的精确处理（23:59:59 还是 00:00:00）
- 金额刚好等于门槛
- 折扣后金额为 0 或负数
- 商品部分适用券（如何分摊抵扣）
- 叠加计算顺序（先券后活动 vs 先活动后券）
- 并发使用同一张券
- 券模板修改后已领取券的行为

## 3. 订单领域（Order）

### 核心实体
- 订单（Order）：主订单
- 订单项（Order Item）：商品明细
- 订单状态流转（Order State Machine）
- 订单快照（Order Snapshot）：下单时的商品/价格快照

### 必查要点

**订单创建**
- [ ] 商品校验（上架状态、库存、限购）
- [ ] 价格校验（前端价 vs 后端价——以后端为准）
- [ ] 价格快照保存（下单时锁定价格）
- [ ] 库存扣减时机（下单扣减 vs 支付扣减）
- [ ] 优惠计算（券、活动、积分）
- [ ] 运费计算
- [ ] 税费计算
- [ ] 防重复下单（幂等键）
- [ ] 订单号生成规则（唯一性、可读性、防猜测）

**订单状态机**
- [ ] 所有状态定义（待支付、已支付、待发货、已发货、已完成、已取消、已关闭）
- [ ] 所有状态转换及触发条件
- [ ] 不可逆转换（如已发货不可回退）
- [ ] 超时自动转换（如 30 分钟未支付自动关闭）
- [ ] 状态转换的并发控制

**订单修改**
- [ ] 哪些字段可改（地址、备注）vs 不可改（金额、商品）
- [ ] 可改的状态范围
- [ ] 修改审计

**订单取消**
- [ ] 可取消的状态范围
- [ ] 取消原因记录
- [ ] 取消后的副作用（释放库存、退券、退款）
- [ ] 用户取消 vs 系统取消 vs 运营取消

**订单拆分/合并**
- [ ] 拆单规则（按商户、按仓库、按商品类型）
- [ ] 父子订单关系
- [ ] 拆单后的金额分摊

**常见边界情况**
- 库存不足时的部分成交
- 价格变动（下单后商品降价）
- 商品下架（订单已创建未支付）
- 并发下单超卖
- 订单超时与支付的竞态（支付成功的同时订单被关闭）

## 4. 认证与授权领域（Auth）

### 核心实体
- 用户（User）
- 会话（Session）/ 令牌（Token）
- 角色/权限（Role / Permission）

### 必查要点

**注册**
- [ ] 注册方式（账号密码、手机号、邮箱、第三方）
- [ ] 唯一性校验（用户名、手机号、邮箱）
- [ ] 密码强度规则
- [ ] 密码加密存储（算法、盐值）
- [ ] 验证码机制（图形、短信、邮箱）
- [ ] 注册后的默认状态（需激活、直接可用）
- [ ] 防刷注册（IP 限制、设备限制）

**登录**
- [ ] 登录方式（密码、短信、扫码、第三方）
- [ ] 登录失败处理（错误次数、锁定、延时）
- [ ] 登录设备记录
- [ ] 异地登录检测
- [ ] Token 生成（JWT 结构、有效期、签名算法）
- [ ] Token 刷新机制
- [ ] 多端登录互斥/共存

**鉴权**
- [ ] Token 验证流程
- [ ] Token 失效处理（过期、被撤销）
- [ ] 权限校验（路由级、操作级、数据级、字段级）
- [ ] 角色继承（如有）
- [ ] 权限缓存

**登出**
- [ ] Token 失效（黑名单、白名单）
- [ ] 多端登出（仅当前端 vs 所有端）
- [ ] 登出审计

**密码管理**
- [ ] 修改密码流程
- [ ] 找回密码流程
- [ ] 密码重置后的副作用（其他端登出）
- [ ] 历史密码校验（不能与最近 N 次相同）

**第三方登录**
- [ ] OAuth 流程
- [ ] 账号绑定/解绑
- [ ] 第三方信息同步

**常见边界情况**
- Token 过期与刷新的竞态
- 并发登录
- 账号注销后数据清理
- 权限变更后的实时生效

## 5. 库存领域（Inventory）

### 必查要点

**库存模型**
- [ ] 库存类型（可售库存、锁定库存、安全库存）
- [ ] 库存单位（SKU、SPU）
- [ ] 多仓库库存

**库存扣减**
- [ ] 扣减时机（下单、支付、发货）
- [ ] 并发控制（防超卖）
- [ ] 部分扣减（库存不足时）
- [ ] 预占与释放

**库存回滚**
- [ ] 订单取消释放
- [ ] 支付超时释放
- [ ] 退款回滚

**库存同步**
- [ ] 实时同步 vs 异步同步
- [ ] 与外部 WMS 的同步
- [ ] 库存差异处理

**常见边界情况**
- 并发下单超卖
- 库存为 0 的展示
- 负库存允许（预售）
- 库存调整的审计

## 6. 消息通知领域（Notification）

### 必查要点

**通知渠道**
- [ ] 短信、邮件、站内信、推送、微信模板消息
- [ ] 渠道选择逻辑（用户偏好、消息类型）

**通知触发**
- [ ] 触发事件（订单状态变更、支付成功、优惠到账）
- [ ] 触发条件（如"金额大于 1000 才发短信"）
- [ ] 防重复发送

**通知模板**
- [ ] 模板管理（变量、多语言）
- [ ] 模板渲染逻辑

**发送策略**
- [ ] 即时发送 vs 批量发送
- [ ] 失败重试
- [ ] 频率控制（防骚扰）
- [ ] 退订机制

**常见边界情况**
- 用户关闭通知权限
- 手机号/邮箱为空
- 模板变量缺失
- 第三方发送服务异常

## 8. 文件上传领域（File Upload）

### 必查要点

**上传校验**
- [ ] 文件类型（MIME、扩展名、文件头）
- [ ] 文件大小
- [ ] 文件名净化
- [ ] 图片尺寸/分辨率
- [ ] 病毒扫描（如有）

**上传方式**
- [ ] 直传到对象存储（预签名 URL）
- [ ] 服务端中转
- [ ] 分片上传（大文件）
- [ ] 断点续传

**存储**
- [ ] 存储路径规则
- [ ] 命名规则（防冲突、防猜测）
- [ ] 访问权限（公开、私有、临时 URL）
- [ ] 生命周期（过期删除、归档）

**安全**
- [ ] 防跨目录
- [ ] 防 SSRF（如从 URL 拉取）
- [ ] 私有文件的鉴权访问

## 使用建议

1. **先识别领域**：分析前先判断功能属于哪个领域，可能有多个（如"优惠券支付"同时涉及优惠券和支付）。

2. **逐项检查**：用对应领域的清单逐项检查代码，确保不遗漏。

3. **跨领域联动**：注意领域间的联动规则，如"使用优惠券的订单退款时如何退券"——这同时涉及优惠券和订单两个领域。

4. **补充而非替代**：这些清单是补充，不替代 `extraction-checklist.md` 的通用检查。两者结合使用。

5. **领域未覆盖时**：如果功能不在上述领域内，参考已有领域的分析思路，自行总结该领域的必查要点。
