# 业务逻辑抽取完整性检查清单

定稿前逐项检查。每一项都是容易遗漏但至关重要的业务逻辑承载点。如果某项不适用，标注"不适用"及原因；如果适用但未在规格中体现，回到代码补充。

---

## A. 数据层（Database & Persistence）

- [ ] **所有相关实体/表**都已识别并列出
- [ ] **每个字段的类型、约束、默认值**已记录（非空、唯一、长度限制、枚举值）
- [ ] **表间关系**已记录（一对多、多对多、外键、级联策略）
- [ ] **唯一约束**已记录（它们往往是业务规则，如"一个用户只能有一张有效主卡"）
- [ ] **Check 约束**已记录（如"金额必须大于 0"、"状态必须在枚举范围内"）
- [ ] **索引**已记录（索引暗示了常见的查询模式和唯一性要求）
- [ ] **软删除字段**及其行为已记录（删除时是否级联、查询时是否自动过滤）
- [ ] **审计字段**已记录（created_at、updated_at、created_by 等）
- [ ] **乐观锁/版本号字段**已记录
- [ ] **数据迁移历史**中是否有关键的业务规则变更（如"v3 后不允许负库存"）

## B. API 层（Backend Interface）

- [ ] **所有相关端点**已列出（包括 REST、GraphQL、RPC）
- [ ] **每个端点的 HTTP 方法、路径、认证要求**已记录
- [ ] **请求参数**：必填/可选、类型、校验规则、默认值
- [ ] **响应结构**：成功响应、各种错误响应
- [ ] **错误码与错误消息**完整列出（包括 i18n 文案）
- [ ] **幂等性要求**已说明（哪些接口需要幂等键、如何实现）
- [ ] **限流策略**已记录（按用户、按 IP、按接口）
- [ ] **请求体大小限制、超时设置**
- [ ] **CORS 配置**（如果前端跨域调用）
- [ ] **API 版本控制**策略

## C. 业务规则层（Domain Logic）

- [ ] **所有校验规则**已记录（格式校验、业务校验、跨字段校验）
- [ ] **计算规则**已记录（价格计算、折扣计算、积分计算、税率等，含公式）
- [ ] **状态机**已完整画出（所有状态、所有转换、触发条件、守卫条件）
- [ ] **权限规则**已记录（谁能做什么、数据权限范围、字段级权限）
- [ ] **业务流程的顺序依赖**已说明（如"必须先实名认证才能提现"）
- [ ] **并发控制**已说明（哪些操作需要锁、用什么锁、锁的粒度）
- [ ] **事务边界**已说明（哪些操作必须原子完成）
- [ ] **定时任务/后台任务**已记录（执行频率、处理逻辑、失败重试）
- [ ] **事件/消息**已记录（发布什么事件、订阅什么事件、消息结构）
- [ ] **配置项**已记录（哪些行为可通过配置改变、默认值、取值范围）

## D. 前端层（Frontend）

- [ ] **所有相关页面/路由**已列出
- [ ] **页面状态机**已记录（加载态、空态、错误态、正常态、禁用态）
- [ ] **表单校验规则**已记录（前端校验往往与后端不完全一致，要分别记录）
- [ ] **用户交互流程**已记录（点击、输入、拖拽等触发的行为）
- [ ] **API 调用时机**已记录（页面加载时、用户操作时、定时轮询）
- [ ] **本地状态管理**已记录（存在哪、如何更新、何时清除）
- [ ] **本地缓存策略**已记录（缓存什么、缓存多久、何时失效）
- [ ] **防重复提交**机制已记录（按钮禁用、节流、防抖）
- [ ] **错误展示**方式已记录（toast、弹窗、行内、跳转错误页）
- [ ] **加载体验**已记录（骨架屏、spinner、进度条、禁用交互）
- [ ] **权限控制**已记录（菜单显隐、按钮显隐、路由守卫）
- [ ] **国际化文案**已收集（至少关键文案）
- [ ] **响应式/适配**规则已记录（移动端、平板、桌面端差异）

## E. 集成层（Integration）

- [ ] **外部服务调用**已列出（第三方 API、SDK）
- [ ] **每个外部调用的契约**已记录（请求、响应、错误处理、超时、重试）
- [ ] **Webhook/回调**已记录（接收哪些回调、如何处理、如何防重放）
- [ ] **内部服务依赖**已记录（依赖哪些内部服务、调用链路）
- [ ] **消息队列**已记录（生产什么、消费什么、队列/主题名、消费组）
- [ ] **文件存储**已记录（上传到哪、如何访问、权限控制、生命周期）
- [ ] **缓存系统**已记录（缓存什么、缓存策略、失效机制）

## F. 安全与合规

- [ ] **认证机制**已记录（登录方式、token 类型、有效期、刷新机制）
- [ ] **授权机制**已记录（RBAC、ABAC、ACL 等）
- [ ] **敏感数据处理**已记录（加密存储、脱敏展示、传输加密）
- [ ] **审计日志**已记录（记录什么、记录在哪、保留多久）
- [ ] **防滥用机制**已记录（验证码、频率限制、设备指纹）
- [ ] **合规要求**已记录（如 PCI DSS、GDPR、等保——如果代码中有体现）
- [ ] **数据保留与删除策略**已记录

## G. 边界情况与异常处理

- [ ] **空值/null 处理**已记录
- [ ] **边界值处理**已记录（最小值、最大值、0、负数、超大数）
- [ ] **并发场景**已记录（同时下单、同时支付、同时修改）
- [ ] **网络异常**处理已记录（超时、断网、DNS 失败）
- [ ] **外部服务异常**处理已记录（第三方宕机、返回异常数据）
- [ ] **部分失败**处理已记录（批量操作中部分成功部分失败）
- [ ] **重试机制**已记录（哪些操作可重试、重试次数、退避策略）
- [ ] **补偿机制**已记录（如支付成功但订单创建失败如何回滚）
- [ ] **时区处理**已记录（存储时区、展示时区、跨时区计算）
- [ ] **货币精度**已记录（用什么类型存储、计算精度、展示精度、舍入规则）

## H. 测试覆盖

- [ ] **单元测试**中揭示的边界条件已提取
- [ ] **集成测试**中揭示的流程已提取
- [ ] **测试中的 mock 数据**揭示了哪些外部依赖
- [ ] **测试中的断言**揭示了预期行为
- [ ] **未覆盖的场景**已标注（如果明显存在但无测试）

## I. 文档与注释

- [ ] **代码注释**中的业务说明已提取
- [ ] **README/文档**中的相关说明已提取
- [ ] **Commit message**中是否有重要的业务变更说明
- [ ] **TODO/FIXME/HACK**注释已检查（它们往往揭示已知问题或待完善的业务规则）

## J. 规格文档质量

- [ ] **术语表**已建立，所有领域术语有定义
- [ ] **每个规则都有明确的触发条件和结果**
- [ ] **状态机图**完整且无死状态、无不可达状态
- [ ] **数据流图**清晰展示数据如何在系统间流动
- [ ] **时序图**覆盖所有关键场景
- [ ] **硬约束与软约束**已区分标注
- [ ] **不确定的地方**已明确标注，并附上需要向用户确认的问题
- [ ] **技术栈无关**——没有出现特定框架的 API 调用
- [ ] **自包含**——无需访问原始代码即可理解
