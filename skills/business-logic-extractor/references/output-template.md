```
        │            │             │（创建新记录）
        ▼            ▼             ▼
   ┌─────────┐  ┌─────────┐

   └─────────┘  └─────────┘
                     │

                     │（创建新记录）
                     ▼
                ┌─────────┐
                │ PENDING │
                └─────────┘
```

**状态转换规则**：

| 当前状态 | 目标状态 | 触发条件 | 守卫条件 |
|----------|----------|----------|----------|
| PENDING | SUCCESS | 收到支付成功回调 | 验签通过 + 金额一致 |
| PENDING | FAILED | 收到支付失败回调 | 验签通过 |
| PENDING | CLOSED | 用户取消 / 超时（30分钟） | 未收到任何回调 |
| SUCCESS | (终态) | — | 不可转换 |
| FAILED | (终态) | — | 不可转换，需创建新支付记录重试 |
| CLOSED | (终态) | — | 不可转换，需创建新支付记录重试 |

## 5. API 契约

### 5.1 端点列表

| 方法 | 路径 | 说明 | 认证 |
|------|------|------|------|
| POST | /api/v1/payments | 创建支付 | 用户 Token |
| GET | /api/v1/payments/{id} | 查询支付状态 | 用户 Token |

| POST | /api/v1/payments/{id}/close | 关闭支付 | 用户 Token |

### 5.2 端点详情

#### POST /api/v1/payments — 创建支付

**请求头**：
```
Authorization: Bearer {user_token}
Content-Type: application/json
```

**请求体**：
```json
{
  "order_id": 12345,
  "channel": "WECHAT",
  "idempotent_key": "uuid-v4-string"
}
```

**字段说明**：

| 字段 | 类型 | 必填 | 校验规则 |
|------|------|------|----------|
| order_id | 整型 | 是 | 必须存在且属于当前用户 |
| channel | 字符串 | 是 | 枚举：WECHAT / ALIPAY |
| idempotent_key | 字符串 | 是 | UUID 格式，同一 key 重复请求返回同一结果 |

**成功响应**（200）：
```json
{
  "payment_no": "PAY202401010001",
  "channel": "WECHAT",
  "amount": 9900,
  "status": "PENDING",
  "wechat_pay_params": {
    "appId": "...",
    "timeStamp": "...",
    "nonceStr": "...",
    "package": "prepay_id=...",
    "signType": "RSA",
    "paySign": "..."
  }
}
```

**错误响应**：

| HTTP 状态 | 业务错误码 | 说明 |
|-----------|-----------|------|
| 400 | INVALID_PARAM | 参数校验失败 |
| 401 | UNAUTHORIZED | 未登录或 token 失效 |
| 403 | ORDER_NOT_YOURS | 订单不属于当前用户 |
| 409 | ORDER_ALREADY_PAID | 订单已支付 |
| 409 | PAYMENT_IN_PROGRESS | 已有进行中的支付 |
| 422 | ORDER_STATUS_INVALID | 订单状态不允许支付（如已取消） |
| 500 | CHANNEL_ERROR | 调用支付渠道失败 |

**幂等性**：基于 `idempotent_key`，相同 key 的请求在 24 小时内返回首次创建的结果。

## 6. 业务规则

### 6.1 校验规则

#### 6.1.1 创建支付校验

| 序号 | 规则 | 类型 | 失败结果 |
|------|------|------|----------|
| 1 | 用户必须已登录 | 硬约束 | 401 UNAUTHORIZED |
| 2 | order_id 必须存在 | 硬约束 | 404 ORDER_NOT_FOUND |
| 3 | 订单必须属于当前用户 | 硬约束 | 403 ORDER_NOT_YOURS |
| 4 | 订单状态必须为"待支付" | 硬约束 | 422 ORDER_STATUS_INVALID |
| 5 | 订单不能已有进行中的支付 | 硬约束 | 409 PAYMENT_IN_PROGRESS |
| 6 | 订单创建时间不能超过 30 分钟 | 硬约束 | 422 ORDER_EXPIRED |
| 7 | channel 必须在支持列表内 | 硬约束 | 400 INVALID_PARAM |
| 8 | idempotent_key 必须为 UUID 格式 | 硬约束 | 400 INVALID_PARAM |

### 6.2 计算规则

#### 6.2.1 支付金额计算

```
支付金额 = 订单应付金额
订单应付金额 = 商品总价 - 优惠抵扣 - 积分抵扣 + 运费
```

**精度规则**：
- 所有金额以"分"为单位存储为整型
- 优惠抵扣按比例分摊到每个商品项，末项兜底（保证总和一致）
- 积分抵扣比例：100 积分 = 1 元

[见 4.3 状态机]

| 操作 | 所需权限 | 数据范围 |
|------|----------|----------|
| 创建支付 | 普通用户 | 仅自己的订单 |

## 9. 安全与合规

### 9.1 认证

- 用户接口需 Bearer Token 认证
- 微信回调通过签名验证，不需 Token

### 9.2 授权

- 用户只能操作自己的订单/支付
- 运营操作需额外角色校验

### 9.3 数据保护

- 微信商户证书、API 密钥存储在配置中心，不落代码库
- 支付日志脱敏：不记录完整卡号、不记录签名串
- 用户手机号在日志中脱敏（保留前 3 后 4）

### 9.4 审计日志

| 操作 | 记录内容 |
|------|----------|
| 创建支付 | 用户 ID、订单 ID、金额、渠道、IP |
| 支付成功 | 支付单号、订单 ID、渠道交易号、金额 |
| 退款发起 | 操作人、支付单号、退款金额、原因 |
| 手动关闭支付 | 操作人、支付单号、原因 |

### 9.5 防滥用

- 单用户每分钟最多创建 10 次支付
- 单 IP 每分钟最多创建 30 次支付
- 风控接口校验：新设备首单限额、异地登录限额

## 10. 边界情况与错误处理

### 10.1 边界值

| 场景 | 处理 |
|------|------|
| 支付金额为 0 | 拒绝，返回 INVALID_PARAM |
| 支付金额超过单笔上限（5 万元） | 拒绝，返回 AMOUNT_EXCEED_LIMIT |
| 订单包含 100+ 商品项 | 正常处理，但需注意分摊计算性能 |
| 同一订单连续发起 5 次支付失败 | 锁定 30 分钟，需联系客服 |

### 10.2 并发场景

| 场景 | 处理 |
|------|------|
| 同一订单同时发起两次支付 | 数据库唯一约束拦截（order_id + status=PENDING），第二个请求返回 409 |
| 回调与轮询同时更新状态 | 使用乐观锁（version 字段），更新失败的一方重试或忽略 |
| 重复回调到达 | 通过回调流水号去重，已处理直接返回成功 |

### 10.3 失败恢复

| 场景 | 恢复策略 |
|------|----------|
| 微信回调未到达 | 定时任务每 5 分钟扫描 PENDING 超过 5 分钟的支付，主动查询微信 |
| 主动查询发现已支付但本地未更新 | 补偿更新 + 发送支付成功事件 |
| 主动查询发现已关闭 | 更新本地状态为 CLOSED |
| 消息发送失败 | 本地消息表 + 定时重投 |

## 11. 实现备注

### 11.1 关键算法

#### 11.1.1 金额分摊算法

```
输入：总价 total、优惠 discount、商品项数 n
输出：每项分摊金额 [d1, d2, ..., dn]

ratio_i = price_i / total
d_i = floor(discount * ratio_i)  // 向下取整

// 末项兜底，保证 sum(d_i) == discount
d_n = discount - sum(d_1..d_{n-1})
```

### 11.2 性能考虑

- 支付记录查询走索引（order_id、payment_no、channel_payment_no）
- 回调处理异步化：验签后立即响应，状态更新走异步队列
- 轮询接口走缓存（Redis，TTL 2 秒），避免高频查库

### 11.3 并发控制

- 创建支付：数据库唯一约束（order_id + status=PENDING）+ 悲观锁
- 状态更新：乐观锁（version 字段）
- 回调处理：分布式锁（payment_no 为 key），防止并发回调

### 11.4 事务边界

- 创建支付：订单状态校验 + 微信下单 + 保存支付记录 → 同一事务（微信调用在事务外，避免长事务）
- 回调处理：状态更新 + 发送事件 → 同一事务（使用事务消息或本地消息表）
