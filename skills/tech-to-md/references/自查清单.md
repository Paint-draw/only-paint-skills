# 交付前自查清单

> 先跑 `python scripts/check-doc.py <文档>`，再逐项过这份清单。
> 机械检查只查结构、禁写项与可疑措辞；内容是否讲透，靠这份清单和「口述验收」。

---

## 一、结构

- [ ] 文首有定位段：这份文档讲什么、不讲什么、文末有哪三块。
- [ ] 有「〇、一页概览」：ASCII 链路能从**入口独立走到出口**，中间没有断节。
- [ ] 概览含**失败 / 降级**旁注，不只是成功路径。
- [ ] 有「一句话」总结，且它与链路一致（不是第二套说法）。
- [ ] 章节按**请求链路**排，不按代码目录排。
- [ ] 每个主题五要素齐全：方法 / 实现什么 / 解决什么问题 / 优缺点 / 原来怎么做、哪里不好。
- [ ] 三块收尾齐全：已知的粗糙处 · 被否掉的方案 · 行为变更（没有就写「无」）。
- [ ] 章节编号没有重排、合并（增量模式尤其要查）。
- [ ] 索引表只列 `# / 主题 / 位置`，没有「共 N 个」。
- [ ] 章节标题是机制名，不是文件名。
- [ ] 全仓搜过同主题文档：没有第二份会漂移的地图，或已在文首写清两份的边界。

## 二、内容

- [ ] 每一节都在回答「**用了什么方法实现**」，而不是「调了哪个函数」。
- [ ] 层与层之间写清了**数据形状**（字段 / 结构 / 关键值），不只是说「传了一个对象」。
- [ ] 每个「为什么」都写了**被否掉的 B 方案与它的代价**；没有 B 方案的，说明是硬约束。
- [ ] 每个参数写了三件事：实际值、默认值、覆盖来源。
- [ ] 每个承重点（改错会静默失效）标了 `★★`，且全文数量克制。
- [ ] 失败路径写清了：报错 / 降级 / 回退 / 静默跳过，以及**调用方能否感知**。
- [ ] 跨服务或跨层的隐式传递（身份、租户、trace）写清了谁注入、经过哪几跳、漏了会怎样。
- [ ] 内部术语首次出现有一句话定义。
- [ ] 自研 / 调库 / 包装的边界写清了（读者能回答「这是你们写的还是库干的」）。

## 三、证据

- [ ] 实测、读码、推断、未核四档分开写，没有混用语气。
- [ ] 每个「实测」都写得出命令与关键输出。
- [ ] 每个「推断」都写了推断依据。
- [ ] 所有没取证的点都显式标了 `未核`。
- [ ] 代码锚点用 `path::symbol`；带行号的已声明抽取点并说明会漂。
- [ ] 没有把一次性读数写成永久事实；数值都带来源。
- [ ] 没有用「测试全绿」替代端到端验证，或在用了时标明验到了什么。
- [ ] 关键结论的实测命令与条件、以及未核项，已写进文末「取证方式与未核项」附录（或在正文就地交代）。

## 四、禁写项

逐条确认文档里**没有**：

- [ ] 日期锚：`2026-10-08`、`（2026-…追加）`。
- [ ] 批次词：`本批 / 本轮 / 本次 / 收口态 / （最新）`。
- [ ] 提交 sha、分支名、部署与 reload 时间戳。
- [ ] 测试计数沿革（`215 → 227`）与「已过验收」。
- [ ] 「已上线 / 已部署 / 已发布」这类交付状态。
- [ ] 台账编号（`N233`）、「见总账 §X」、计划 / spec 文件名。
- [ ] 订正沿革（「原文如此，已订正为…」）。
- [ ] 单 `★`（只允许 `★★`）。

## 五、口述验收

- [ ] 只用「〇、一页概览」，能在 **60 秒**内讲完整条链路。
- [ ] 任挑一节，能讲 **3 分钟**：方法 → 为什么 → 代价 → 失败怎么办。
- [ ] 「分节一句话」每行都成立，且没有引入正文之外的新事实。
- [ ] 列出**最可能被追问的 5 个问题**，逐个能在正文找到答案。
- [ ] 找一个没读过这个模块的人试讲一遍，记录他卡住的地方——卡点就是文档的缺口。

## 六、增量模式附加检查

- [ ] 旧文的每个 `§N` 都还在原位，或已说明为什么不能保留。
- [ ] 「行为变更」只追加，没有改写历史行。
- [ ] 已销账的「粗糙处」在「行为变更」里有对应记录，且没有写订正沿革。
- [ ] 旧文中的事实已**重新取证**，不是照抄上一版。
