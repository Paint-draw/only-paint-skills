# 业务逻辑 · 执行计划（To Code）

把 `docs/business-logic/plan/` 里的计划文档一比一落地成代码，并保证白皮书同步。

> 可执行细节在 `references/mode3-execute.md`（执行边界、验证分层、失败分支、审查流程、同步核对）。
> 模板在 `assets/计划文档.template.md`。

## 先进路由判断

| 情况 | 行动 |
|------|------|
| 手上有 `docs/business-logic/plan/` 里的计划文档 | **走我的主流程** |
| 没有计划文档 | **不是我管** → 引导用户用 `business-logic:improve` 出计划 |
| 只有完善文档、没有计划文档 | **不是我管** → 完善文档只是需求分析，还需要拆成计划才能执行 |

## 前置

手上要有计划文档。没有 → 先用 `business-logic:improve`。

## 主流程：六步落地

### 1. 执行
用 `superpowers:executing-plans` **分步实现、一步一验**，不一口气冲到底。高风险/迁移/删除步骤做完先停下汇报。卡壳走 `superpowers:systematic-debugging`。

**工作区隔离——按规模自判，不盲开 worktree**：
- **小改动**（1-2 文件、单模块、修 bug）→ 直接在当前工作区改，`git stash` / `git checkout` 回滚就够。开 worktree 浪费时间和上下文。
- **中改动**（3-10 文件、单模块重构）→ 看情况：git 状态干净就直接改；想双轨并行或状态不干净才开 worktree。
- **大改动**（10+ 文件、跨模块、数据库迁移、破坏性变更）→ 用 `superpowers:using-git-worktrees` 隔离。坏了丢掉整个 worktree，主区毫发无伤。

worktree 是安全网，不是手铐——大部分日常执行不需要它。

### 2. 验证
用 `superpowers:verification-before-completion`，**按改动面选层级**（详见 `references/mode3-execute.md` 第二节）：

| 层级 | 做什么 | 何时必须 |
|------|--------|----------|
| L0 编译/构建 | build 通过 | 永远——但 build 通过 ≠ 功能完成 |
| L1 单元测试 | 跑相关单测 | 改了后端规则/纯函数/算法 |
| L2 集成测试 | 跑集成/EF 测试 | 改了数据访问、跨服务、事务 |
| L3 接口冒烟 | Swagger/curl 调真实接口 | 改了任何接口（路径/参数/权限/返回） |
| L4 端到端 | 各端点进真实页面走一遍 | 改了用户可见流程 |

跑命令看真实输出。build 通过 ≠ 功能完成。

### 3. 代码审查
用 `superpowers:requesting-code-review`，**必须带业务背景**（完善文档+预期行为+重点关注：业务规则/状态分支/`[[id]]` 受影响功能是否同步改/项目 `docs/rules/` 强约束）。意见分**阻塞级/建议级**。收到审查用 `superpowers:receiving-code-review` 理性对待。

### 4. 失败与冲突
- 执行失败 → debug → 重跑该步。连续卡住 → 停下回报。
- 验证不过 → 回执行修，不得带病进审查。
- **验证与审查冲突**：任一维度"不过/阻塞"都拦收尾。只有两边绿灯才算完成。

（详见 `references/mode3-execute.md` 第五节）

### 5. 收尾：确认白皮书已同步
**放在验证过 + 审查无阻塞之后**。按 `references/mode3-execute.md` 第七节核对：
- 对应模块文档 + 每个 `[[id]]` 受影响模块都回写了？
- 根白皮书状态/最近更新更新了？
- frontmatter 记了关联计划+提交？

**不同步 = 白皮书和代码脱节，本流程最容易漏的坑。**

### 6. 交接验收
向用户汇报——做了什么、验证到哪层（真实结果）、审查结论、文档同步了哪些——**请用户验收**。用户点头才算完成。

## 多模块并行修改
计划涉及多个模块时：
- **验证**：分模块验（各自 L1/L3），最后跨模块 L4 联动验。
- **审查**：按模块分别审，再整体审接缝处。
- **收尾同步**：拿完善文档 `[[id]]` 清单逐个核，每个被改模块都要回写。

## 编排 / 复用的技能

| 场景 | 技能 |
|------|------|
| 大改动隔离 / 回滚保险 | `superpowers:using-git-worktrees` |
| 分步执行计划 | `superpowers:executing-plans` |
| 调试 | `superpowers:systematic-debugging` |
| 完成前验证 | `superpowers:verification-before-completion` |
| 代码审查 | `superpowers:requesting-code-review` |
| 理性对待审查意见 | `superpowers:receiving-code-review` |

## 铁律速查

- **没计划不进③**：手上要有计划文档。
- **分步验、带背景审、按层级验**：一步一验；审查带业务背景+意见分级。
- **验证和审查任一阻塞都拦收尾**：只有两边都绿灯才算完成。
- **收尾必核对白皮书已同步**：文档回写 + 白皮书更新 + 溯源登记。
- **交接验收是最后一步**：用户点头才算完。
